# Как это устроено

## Конвейер ID-карты

```
фото/скан ──► 1. выравнивание по эталону ──► 2. поля по зонам ──► 4. сверка ──► /passport
   (обе        SIFT + гомография,             Tesseract tgk/eng     MRZ, ФИО,       │
   стороны)    определение стороны            по каждому полю       10 лет           ▼
                       │                                                         5. HR-маппинг
                       └──────────────► 3. MRZ (ocrb) + контрольные цифры          18 полей, tg/en,
                                                                                   scores, needs_review
```

1. **Выравнивание** (`app/passport/align.py`). Дизайн карты одинаков у всех: флаг, герб, подписи
   полей, фоновый узор. Ключевые точки SIFT сопоставляются с обезличенными эталонами
   (`app/passport/templates/`), по ним считается гомография, и карта перерисовывается
   в 1024×640. Это не зависит от фона, обрезки краёв, поворота и перспективы. Эталон с большим числом
   совпадений определяет сторону. Сопоставление детерминированное (BFMatcher, фиксированное зерно
   RANSAC): один и тот же снимок всегда даёт один результат. Запасной путь — поиск контура карты
   (`card.py`).
2. **Поля по зонам** (`layout.py`, `reader.py`). Каждое поле вырезается по своей зоне, обрезается
   до самой «жирной» строки текста и читается отдельной моделью: `tgk` — кириллица, `eng` —
   латиница и цифры (с ограничением набора символов), с проверкой формата (даты, длина номеров).
   Семейное положение и коды стран — по словарю.
3. **MRZ** (`mrz.py`). Три строки TD1 читаются моделью OCR-B (`ocrb`) в нескольких вариантах
   (выпрямление, масштаб, бинаризация); лучший выбирается по четырём контрольным цифрам ICAO 9303.
   Похожие символы исправляются по позиции (в числовом поле `O→0`, в буквенном `0→O`). Номер
   таджикской карты обязан быть «буква + 8 цифр» — иначе даже сошедшаяся контрольная цифра
   не считается подтверждением.
4. **Сверка** (`reader.merge`).
   - Номер документа, даты, пол, гражданство, личный номер — с MRZ.
   - ФИО — голосованием трёх независимых чтений (кириллица, латиница, MRZ) через таджикскую
     транслитерацию (`translit.py`) с учётом ошибок OCR: Ч/Ҷ, Х/Ҳ, К/Қ, Г/Ғ, Л/П/Д, потерянные Ё/Ӯ/Ӣ,
     пропущенная, лишняя буква или пробел. Расхождение латиницы карты и MRZ помечается.
   - Адрес — словарём служебных слов и всех районов Таджикистана (ЗИДОЯТИ → ВИЛОЯТИ,
     склеенное ВИЛОЯТИХАТЛОН → ВИЛОЯТИ ХАТЛОН).
   - Срок действия = дата выдачи + 10 лет − 1 день.
5. **HR-маппинг** (`app/hr/mapping.py`). Поля карты → анкета из 18 полей, язык, разбор адреса
   на регион/город/деревню, `scores` и `needs_review` (правила — в [hr-api.md](hr-api.md)).

Общая точка входа для обоих API — `app/passport/service.py: read_passport()`.

## Модули

```
app/
  main.py               FastAPI: lifespan (проверка Tesseract и моделей, загрузка эталонов), /health, роутеры
  config.py             настройки из окружения (pydantic-settings)
  ocr.py                /ocr: произвольный текст
  images.py             загрузка изображения: лимит размера, тип, EXIF-поворот
  preprocess.py         выравнивание освещения, выпрямление наклона
  tess.py               вызов Tesseract, проверка моделей (TESSDATA_DIR)
  passport/
    align.py            выравнивание по эталону, определение стороны
    templates/          обезличенные эталоны сторон и маски
    card.py             запасной поиск карты по контуру
    layout.py           зоны полей на карте 1024×640
    reader.py           чтение зон, MRZ, сверка → Field(value, raw, confidence, verified, note)
    mrz.py              разбор TD1, контрольные цифры
    translit.py         таджикская транслитерация, исправление ФИО и адресов, словарь мест
    service.py          read_passport(): общий вход для /passport и /hr
    router.py           /passport, /passport/front, /passport/back
  hr/
    mapping.py          поля карты → анкета HR, языки, scores, needs_review
    router.py           /hr/passport, /hr/fields
```

## Почему так

- **Tesseract `tgk`, а не PaddleOCR.** Официальная кириллическая модель PaddleOCR не знает Ӯ и Ӣ
  и путает ҳ/х, ҷ/ч (на тестовом наборе — 33% верных таджикских букв против 100% у `tgk`).
  В ветке `internal-deploy` Paddle удалён совсем.
- **Зоны после выравнивания, а не поиск подписей по всей странице.** Отдельная зона позволяет
  читать каждое поле своей моделью и с ограничением набора символов; выравнивание по эталону
  делает зоны точными на любых фото.
- **Несколько независимых чтений вместо одного «умного».** Ошибки OCR редко совпадают в разных
  источниках (кириллица, латиница, MRZ), поэтому их согласие — надёжный признак правильности,
  а несогласие — честный повод показать поле человеку.

## Известные ограничения

- Только ID-карта образца 2017+. Старый паспорт-книжка — другая MRZ (TD3, 2×44) и другой макет.
- Шрифт генератора образцов похож на шрифт карты, но не совпадает: оценки на синтетике
  ориентировочные. Реальные данные: 3 карты (см. [testing.md](testing.md)).
- Ӯ/Ӣ vs У/И в ФИО не проверяются латиницей.
- РМА (ИНН) не имеет контрольной цифры и на фото читается хуже всего.
